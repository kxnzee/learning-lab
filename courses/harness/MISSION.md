# Миссия: харнесы — выбрать для себя и построить для аналитиков

Тип: research → practice

## Зачем
Лично мне — осознанно выбрать харнес для своей работы. Для кластера (ИИ-трансформация в банке) — построить харнес, который автоматизирует работу аналитиков и помогает им расти. Сейчас есть эксперименты, сделанные на интуиции (OpenSpec Orchestrator, SDD-процесс); нужна модель, чтобы решать осознанно.

## Успех — это
- [ ] Раскладываю любой харнес по одной схеме слоёв (цикл, инструменты, контекст, скиллы, хуки, субагенты, память, права) и объясняю, какую проблему решает каждый слой
- [ ] Сравнил основные харнесы по критериям моей работы и выбрал свой с обоснованием
- [ ] Знаю, какие приёмы Superpowers и ECC брать для аналитиков, а какие нет, и почему
- [ ] Умею измерять, стал ли харнес лучше после изменения (evals)
- [ ] Объясняю каждое ключевое решение в своём Orchestrator: почему оно верное или что переделать
- [ ] Есть архитектура и дорожная карта харнеса для аналитиков, которую можно защитить перед руководством

## Ограничения
- В банке: агенты Claude, Qwen, GigaCode; закрытый контур без интернета; обвязка поверх существующих клиентов через MCP
- Для личной работы — уточнить (диагностика, вопрос 5)
- Опора — собственные репозитории: kxnzee/multi-repo-specs, kxnzee/sdd-openspec-process, kxnzee/specs
