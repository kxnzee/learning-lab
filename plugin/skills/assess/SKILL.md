# Assess

Teach хорошо делает следующий урок, но сам не знает, когда остановиться. Assess — эта остановка: сверка с миссией по доказательствам, а не по ощущениям.

Устройство лаборатории и форматы — в скилле `teach`; прочитай его SKILL.md, если ещё не читал в этой сессии.

## 1. Подготовка

Прочитай в `courses/<slug>/`: MISSION.md, все learning records, GLOSSARY.md, список уроков и `lab/`. Выбери один неотмеченный критерий из «Успех — это» — тот, к которому ближе всего по learning records. Ученик назвал другой — бери его.

## 2. Проверка

Проверка проверяет, а не учит: подсказки — только после итога.

1. **Объяснение** — 3–5 вопросов «почему» и «что будет, если» по моделям, на которых держится критерий. Своими словами, без источников. Расплывчатый ответ — уточняющий вопрос, пока не станет ясно, есть понимание или нет.
2. **Действие** — одно новое задание, которое и есть критерий в миниатюре: в `lab/assess-<NNNN>/` или в реальном проекте ученика. Для research-темы — сравнение с альтернативой для конкретного случая ученика или прототип с перечнем ограничений.
3. **Слабые места** — по вопросу на каждое заблуждение из learning records, которое ещё не закреплено.

## 3. Итог

По каждой части: сдано / не сдано и одна фраза почему. Затем одно из трёх:

- **Критерий достигнут** → отметь `[x]` в MISSION.md, запиши learning record с доказательством. Все критерии отмечены → тема в «Освоено» в `dashboard.md`; предложи сообщество из RESOURCES.md, чтобы проверить навык в реальном мире.
- **Почти** → learning records о том, что не хватило; в `dashboard.md` «что дальше» — урок-тренировка по слабым местам.
- **Рано** → learning records о пробелах; «что дальше» — новый урок на недостающий навык.

Карточки по провалам — через скилл `review` (команда `add`), чтобы пробел вернулся в повторение. Сохрани изменения так же, как в шаге 5 скилла `teach`.

Assess завершён, когда у выбранного критерия есть итог с доказательством, а в `dashboard.md` записано, что дальше.
